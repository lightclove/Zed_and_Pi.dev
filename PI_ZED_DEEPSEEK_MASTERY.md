# pi.dev + DeepSeek: учебник по работе с агентом в терминале

**Что здесь описано.** pi — ИИ-агент, который работает в терминале: читает файлы, выполняет команды
и сам правит код по вашим указаниям. DeepSeek — семейство моделей, на которых он работает.

**Для кого:** человек, который впервые открывает pi и хочет не кликать наугад, а понимать, как всё устроено.
**Результат:** от первого запуска до собственных расширений, субагентов (агентов-помощников) и
осознанной траты токенов (единиц текста, по которым тарифицируются запросы к модели — подробнее в разделе 6).

**Как читать.** Части I–III — обязательный путь новичка (3–4 дня; в каждой части есть задание «сделай
руками»). Часть IV — когда базовый цикл «план → код → ревью → шип (сдача)» уже не вызывает вопросов.
Приложения — не для чтения подряд: инвентарь конкретного проекта, журнал чисел и типичных ошибок,
перенос опыта в новые проекты.

**Достоверность.** Цены моделей сверены с локальным каталогом pi (`models-store.json`), цифры стоимости —
пересчитаны командой `pi-cost` по реальным сессиям (2026-10-15). Всё, что относится к «нашему проекту» —
`C:\Users\admin\Work\Zed_and_Pi.dev`.

# Часть I. Первый запуск (день 1)

## 1. Установка и проверка

**Цель:** pi запускается, видит DeepSeek и умеет выполнять shell-команды. Без этого всё остальное не работает.

### 1.1 Git Bash — обязателен на Windows

pi на Windows выполняет команды агента через Git Bash. Без него агент не может запустить ни одной
команды — только читать и писать файлы.

```text
1. Установи Git for Windows: https://git-scm.com/download/win
2. В pi введи:  !printf 'Bash works\n'
3. Если не подхватилось — в ~/.pi/agent/settings.json:
   "shellPath": "C:\\Program Files\\Git\\bin\\bash.exe"   (путь — по месту установки)
```

### 1.2 Ключ DeepSeek

Ключ живёт в переменной окружения `DEEPSEEK_API_KEY` (или настраивается через `/login deepseek`).
Проверь оба пункта:

```bash
pi auth check --provider deepseek --json
pi --list-models deepseek
```

Должны быть видны модели `deepseek-flash` и `deepseek-v4-pro`.

### 1.3 Первый запуск в папке проекта

При первом запуске в новой папке pi спрашивает **доверие (trust)**: проектные ресурсы (`.pi/`,
`AGENTS.md`) загружаются только после подтверждения. Подтверди, затем `/reload`.

> Задание на день 1: пройди шаги 1.1–1.3 и покажи `pi auth check` с обеими моделями.

## 2. Первый день в терминале: экран, стоп, навигация, сессии

Если ты пришёл из Cursor / Zed / агентных IDE — главное, что нужно перестроить в голове: **здесь нет
кнопок, есть клавиши.** Всё, что в GUI было кнопкой или выпадающим списком, в pi — хоткей или slash-команда.

### 2.1 Экран: три зоны

| Зона в pi | Что это | Аналог в GUI |
|---|---|---|
| Транскрипт (лента сверху) | промпты, ответы, tool calls, вывод | чат-панель |
| Редактор (строка внизу) | сюда набираешь промпт | поле ввода |
| Футер (status bar) | папка, сессия, модель, контекст, стоимость | статус-строка |

Текст в редакторе **не отправляется**, пока не нажмёшь `Enter`. Пока не нажал — можно менять модель,
уровень мышления, редактировать текст, прикладывать файлы (`@`).

### 2.2 Стоп! Как остановить агента

Кнопка «Stop» из GUI — это клавиша **`Escape`**:

- **`Escape`** — прервать текущий ран: агент остановится, сообщения вернутся в редактор.
- `Ctrl+C` — это **НЕ «копировать»** (см. 2.6). Первое нажатие очищает редактор, второе — выходит из pi.
- `Ctrl+D` — выйти из pi (когда редактор пуст).

Пока агент работает, можно не только останавливать, но и управлять:

| Что хочешь | Клавиша (Windows) | Смысл |
|---|---|---|
| Подправить задачу на ходу | набрал текст → `Enter` | steering: встанет после текущего хода |
| Добавить работу после текущей задачи | `Ctrl+Q` | follow-up: выполнится, когда текущая закончится |
| Вернуть отложенные сообщения в редактор | `Alt+Q` | dequeue |
| Остановить совсем | `Escape` | abort |

### 2.3 Навигация по транскрипту

В fullscreen-режиме скроллом владеет pi, поэтому листать — клавишами:

| Действие | Клавиша (Windows) |
|---|---|
| Прокрутка на страницу | `PageUp` / `PageDown` |
| **Вниз + следовать за новым выводом (автоскролл)** | **`End`** |
| В самое начало | `Home` |
| К предыдущему/следующему сообщению | `Ctrl+Up` / `Ctrl+Down` |
| Поиск по транскрипту | `Ctrl+F` (`Enter` — след., `Shift+Enter` — пред., `Esc` — выйти) |
| Развернуть/свернуть вывод инструмента | `Ctrl+O` |
| Свернуть/развернуть thinking | `Ctrl+T` |

**`End` — основная клавиша:** после любой прокрутки вверх он возвращает вниз и снова «следит» за работой
агента. `Ctrl+Up`/`Ctrl+Down` — перемещение между пользовательскими запросами.

### 2.4 Смена модели, не удаляя набранный текст

Модель и уровень мышления меняются **поверх** набранного промпта — текст в редакторе остаётся.

- **`Ctrl+L`** — селектор модели (выпадающий список, как в GUI). Выбрал → `Enter`, промпт не тронут.
- **`Ctrl+P` / `Alt+P`** — следующая / предыдущая модель в цикле.
- **`Shift+Tab`** — цикл уровня мышления (effort).
- `/model` и `/thinking` — то же самое через slash-команды.

Состав цикла настраивается через `/scoped-models`. Текущая модель видна в футере.

### 2.5 Клавиши редактора промпта

Редактор работает как readline/emacs — мыши и выделения здесь нет. Основное:

| Клавиша | Действие |
|---|---|
| `Ctrl+A` / `Ctrl+E` | в начало / в конец строки |
| `Ctrl+Left` / `Ctrl+Right` (`Alt+B` / `Alt+F`) | по слову влево/вправо |
| `Ctrl+W` / `Alt+Backspace` | удалить слово назад |
| `Ctrl+K` / `Ctrl+U` | удалить до конца / до начала строки |
| `Ctrl+Y` | вставить удалённое (yank) |
| `Ctrl+Z` | отмена |
| `Up` / `Down` | история промптов (курсор в начале строки) |
| `Shift+Enter` / `Ctrl+J` | новая строка без отправки |
| `Tab` | автодополнение пути |
| `@` + текст | поиск и прикрепление файла к промпту |
| `Ctrl+G` | открыть промпт во внешнем редакторе (Zed) для длинного текста |

`Enter` = отправить. Многострочный промпт — `Shift+Enter` (или `Ctrl+G` → Zed).

### 2.6 Копирование и вставка — не перепутай `Ctrl+C`

- **`Ctrl+X`** — скопировать последний ответ ассистента (внутри pi).
- Выделение текста терминала — `Ctrl+Shift+C` / `Ctrl+Shift+V` (Windows Terminal) или мышью с `Shift`.
- Вставка изображения/файла в промпт — `Alt+V`.

### 2.7 Shell-команды прямо из pi

Не нужно выходить из pi и открывать второй терминал:

- `!git status` — выполнить команду, **вывод уйдёт модели** (она его увидит).
- `!!git status` — выполнить, **вывод модели не отправляется** (только для себя).

Правило: **`!!` для больших выводов** (например, `!!git diff`) — смотришь сам, агент не платит токенами.

### 2.8 Сессии — это чаты

«Чат» в pi называется **сессией**. Одна сессия = один JSONL-файл в `~/.pi/agent/sessions/`, привязанный
к рабочей папке. Постоянной боковой панели нет — список **открывается командой** `/resume`.

| Задача (как в GUI) | Команда / клавиша | Пояснение |
|---|---|---|
| **Новый чат** | `/new` | новая пустая сессия в той же папке |
| Продолжить последний чат | `pi --continue` | при запуске из терминала |
| **Список чатов / история** | `/resume` | интерактивный селектор; печатай — фильтруется |
| Переключиться на чат | `Enter` в `/resume` | выбрать из списка |
| Переключиться по id | `pi --session <id>` | id виден в `/session` |
| Переименовать чат | `/name Мой-чат` | или `Ctrl+R` в `/resume` |
| Удалить чат | `Ctrl+D` в `/resume` | `Ctrl+Backspace` — без подтверждения, если поиск пуст |
| Инфо о чате (id, токены, стоимость) | `/session` | смотри после каждой задачи |
| Сортировка / пути / только именованные | `Ctrl+S` / `Ctrl+P` / `Ctrl+N` | внутри `/resume` |
| Импортировать сессию | `/import <path>` | перенос чата из другого места |

Осторожно: внутри `/resume` клавиши `Ctrl+P` и `Ctrl+D` значат **не то же**, что в редакторе.

**Ветки — то, чего нет в Cursor.** Сессия — это **дерево**, а не линейный чат. Можно вернуться к любой
реплике и пойти другим путём, не теряя старую ветку:

| Действие | Команда | Когда |
|---|---|---|
| Прыгнуть к более ранней реплике в том же файле | `/tree` | альтернативы должны остаться вместе |
| Сделать из реплики отдельный чат | `/fork` | альтернатива — независимая работа |
| Скопировать текущую ветку в новый чат | `/clone` | нужна отдельная копия состояния |

Сжатие и экспорт: `/compact` — сжать контекст; `/export` / `/share` / `/copy` — сохранить или поделиться
чатом. Эфемерный чат (не сохраняется): `pi --no-session`.

### 2.9 Два режима интерфейса

- **Fullscreen** (по умолчанию): pi владеет экраном, скролл — клавишами (`End`, `PageUp/Down`).
- **Regular** (`/settings` → tui mode, или `--tui-mode regular`): скролл и мышь отданы терминалу,
  выделение мышью и `Ctrl+Shift+C`/`V` работают как обычно.

Многие начинают в regular, потом переходят в fullscreen ради `End`/`Ctrl+O`/поиска.

### 2.10 Шпаргалка-переводчик Cursor/Zed → pi

| В GUI (Cursor/Zed) | В pi (терминал) |
|---|---|
| Кнопка Stop | `Escape` |
| Выпадающий список моделей | `Ctrl+L` (меню) или `Ctrl+P`/`Alt+P` (цикл) |
| Переключатель effort/thinking | `Shift+Tab` |
| Поле ввода чата | редактор внизу, `Enter` = отправить |
| Многострочный ввод | `Shift+Enter` / `Ctrl+J` / `Ctrl+G` (Zed) |
| Боковая панель с чатами / историей | `/resume` (список + поиск) |
| Новый чат | `/new` |
| Переименовать чат | `/name` (`Ctrl+R` в списке) |
| Ветки одного чата | `/tree`, `/fork`, `/clone` |
| Терминальная вкладка | `!команда` / `!!команда` |
| Accept/Apply изменения | агент правит файлы сам — смотри diff (раздел 9) |
| Список всех шорткатов | `/hotkeys` |

**Запомни три вещи:** `Escape` = стоп · `End` = вниз и следить · `Ctrl+L` = сменить модель, не удаляя промпт.

# Часть II. Как это устроено (день 2)

## 4. Ментальная модель pi

**pi — минимальный расширяемый агент для терминала.** Главная идея: «подстрой pi под свой рабочий
процесс, а не наоборот». Всё, что в Cursor «встроено», здесь собирается из маленьких примитивов.

### 4.1 Цикл агента

```
сообщение пользователя → запрос = системный промпт + активная ветка истории
                        + описания инструментов + настройки модели
→ стрим ответа модели (текст + tool calls)
→ pi выполняет каждый tool call и записывает результат
→ если нужен следующий шаг (tool results / очередь сообщений) → новый ход
→ иначе — конец рана
```

- **Steering** (`Enter`) — сообщение встаёт после текущего хода и корректирует задачу.
- **Follow-up** (`Alt+Enter` / на Windows `Ctrl+Q`) — сообщение ждёт завершения текущей задачи.
- **Abort** (`Escape`) — останавливает ран, сообщения возвращаются в редактор.

### 4.2 Контекст

- Строится из **активной ветки** сессии + системного промпта + описаний инструментов + описаний skills.
- Системный промпт = базовые инструкции pi + найденные контекст-файлы (`AGENTS.md`, `CLAUDE.md`,
  `AGENTS.override.md`).
- **Skills** анонсируются именем и описанием, полные инструкции грузятся **по требованию**.
- Расширения могут добавлять инструкции или трансформировать контекст.

### 4.3 Сессии — это дерево

- Сессия = JSONL-файл; сообщения и события образуют **дерево**; путь по дереву = **ветка (branch)**.
- Активная ветка даёт историю для следующего запроса.
- **Компакция** вставляет summary-запись, заменяющую старые сообщения в последующих запросах (оригинал
  остаётся в дереве).
- Продолжить с ранней точки = новая ветка в том же файле. Резюм сессии **сохраняет префикс → кэш-хиты**.

### 4.4 Пять интерфейсов

### 5.1 Актуальный конфиг этого компьютера

### 5.3 DeepSeek + cacheWarming

`cacheWarming` (прогрев кэша в простое/потоке) работает только для моделей с объявленным `promptCache`

`modelOverrides` в `models.json` (см. `docs/models.md`), но сначала проверь реальный TTL кэша DeepSeek
в их документации.

## 6. Модели и деньги: DeepSeek, цены, кэш

### 6.1 Две модели (цены сверены с каталогом pi, `models-store.json`)

| | `deepseek-flash` (V4.1 Flash) | `deepseek-v4-pro` (V4 Pro) |
|---|---|---|
| Input (промах кэша) | **$0.30 / 1M** | $1.32 / 1M |
| Input (попадание кэша, `cacheRead`) | **$0.006 / 1M** (×50 дешевле) | $0.044 / 1M (×30 дешевле) |
| Output | **$1.20 / 1M** | $3.96 / 1M |
| Запись в кэш (`cacheWrite`) | **$0** | $0 |
| Контекст / max output | 1M / 384k | 1M / 384k |
| Вход | текст + **изображения** | только текст |
| Уровни мышления | `low` / `high` / `max` | только `high` / `max` |

Провайдер `deepseek`, base URL `https://api.deepseek.com`, API `openai-completions`.

### 6.2 Механика кэша — главный экономический рычаг

- DeepSeek кэширует **префикс запроса на своей стороне автоматически** — никаких маркеров не нужно.
- **Запись в кэш бесплатна** (`cacheWrite = 0`) — в отличие от Anthropic/OpenAI, где запись дороже обычного ввода.
- Попадание в кэш в **30–50 раз дешевле** промаха. Закон экономии: **держи стабильный префикс** (системный
  промпт + AGENTS.md + набор инструментов + история) и не переключай модель/инструменты посреди задачи.
- Reasoning-токены **остаются в контексте** (`requiresReasoningContentOnAssistantMessages: true`) — они
  пересылаются как часть истории и тарифицируются как output.

### 6.3 Три вывода

1. **Кэш-промах vs попадание = ×30–50.** Стабильный префикс — твой главный актив.
2. **Output (включая reasoning) дороже input в 3–4 раза.** Проси краткие ответы, держи thinking низким.
3. **flash в ~4.4× дешевле pro по input и в 3.3× по output** и при этом мультимодальная → основная рабочая модель.

### 6.4 Имена моделей: flash/v4-pro vs chat/reasoner

Zed настроен на `deepseek-chat` / `deepseek-reasoner` (классические ID публичного API), а каталог pi
использует `deepseek-flash` / `deepseek-v4-pro`. Оба набора могут быть валидными алиасами — сверься с
`api-docs.deepseek.com` и обнови каталог: `pi update --models`. Проверь на своём ключе.

## 7. Экономия токенов

### 7.1 Десять правил

1. **Контекст — единица стоимости.** Сначала `find`/`grep`/`ls`, потом `read` только нужных диапазонов
   (`offset`/`limit`). Никогда не дампь репозиторий целиком.
2. **Локальность кэша.** Не меняй модель/thinking/набор инструментов в середине задачи — каждый switch =
   промах кэша = ×30–50 по вводу на следующем запросе.
3. **Распределение задач по моделям.** `flash` для 90% токенов, `pro` — только для архитектуры/отладки/безопасности.
4. **Бюджет reasoning.** `low` по умолчанию. Reasoning = output-токены, дорогие и накапливаются в контексте.
5. **Компакция.** Окно 1M — не свалка. `/compact` при разрастании; короткая история = дешёвый префикс.
6. **Фильтруй вывод инструментов.** `codemode` режет/агрегирует результат до попадания в контекст.
7. **Параллель вместо последовательности.** Каждый round-trip пересылает весь контекст. Один `codemode`
   с 5 параллельными чтениями лучше 5 последовательных шагов.
8. **Измеряй, а не верь.** Футер (usage/cost), `/session`, `showCacheMissNotices`.
9. **Fork/continue вместо рестарта.** Резюм сохраняет префикс → кэш-хиты с первого запроса.
10. **Точечные правки.** `edit` с маленьким `oldText` вместо перезаписи файла целиком.

### 7.2 Инструменты измерения

- **Футер TUI** — накопленный usage и cost за сессию; с расширением `deepseek-balance` (установлено в этом
  проекте) под ним виден живой баланс аккаунта DeepSeek, `/balance` — повторная синхронизация с сервером.
- **`/session`** — файл, число сообщений, токены, стоимость текущей сессии.
- **`tools/pi-cost/pi-cost.mjs`** — агрегат по всем сессиям `~/.pi/agent/sessions`:
  `node tools/pi-cost/pi-cost.mjs [paths...] [flags]`; `--today`, `--last N`, `--top N`, `--json`.
  Считает все ветки (реальный расход), cache-hit = `cacheRead / (input + cacheRead)`.

### 7.3 Баланс DeepSeek в футере

Расширение `deepseek-balance` (`.pi/extensions/deepseek-balance.ts`, в этом репо и в global) добавляет
под встроенный футер строку с текущим балансом:

```text
deepseek $46.44 left · this session -$0.149
```

**Как работает:**

- При старте сессии один раз запрашивает реальный баланс с `https://api.deepseek.com/user/balance`.
  Ключ берётся из провайдера pi (`ctx.modelRegistry.getApiKeyForProvider("deepseek")`) — ничего не хардкодится.
- Между запросами вычитает траты текущей сессии (usage-записи из `ctx.sessionManager.getEntries()`),
  поэтому цифра обновляется в реальном времени после каждого ответа модели.
- **`/balance`** — принудительная повторная синхронизация с сервером (нужно, если тратил деньги из другого приложения
  или параллельной сессии).
- Ошибки показываются честно: `deepseek balance: HTTP 401` / `no DeepSeek API key (auth.json / DEEPSEEK_API_KEY)`.
- Не путай с встроенной строкой `5.0%/1.0M (auto)` в футере — это рабочая память (заполненность контекста),
  а не деньги.

**Установка:**

```bash
mkdir -p ~/.pi/agent/extensions
cp ~/Work/Zed_and_Pi.dev/.pi/extensions/deepseek-balance.ts ~/.pi/agent/extensions/
# в pi: /reload — в футере появится «deepseek $… left»
```

Нет локальной копии репо — файл можно взять с GitHub:
`https://github.com/lightclove/Zed_and_Pi.dev/raw/main/.pi/extensions/deepseek-balance.ts`

**Ключевые API кода:** `ctx.ui.setStatus(key, text)` — своя строка статуса в TUI; события
`session_start` / `message_end` / `session_compact` — точки обновления; `registerCommand("balance")` —
слаш-команда. Полный код — раздел 15 (инвентарь) и файл `.pi/extensions/deepseek-balance.ts`.

## 9. Диффы: что именно изменил агент

**Главное отличие от Cursor:** pi пишет изменения в файлы **сразу**, кнопки Accept/Reject нет. Значит,
«понять, что изменил агент» = посмотреть **дифф**. Четыре уровня:

**1) Дифф прямо в pi (в транскрипте).** Каждый вызов `edit` рисуется цветным диффом: красный `-` —
удалённые строки, зелёный `+` — добавленные, подсветка внутри строки — изменённые слова, тусклые строки —
контекст. `Ctrl+O` — развернуть/свернуть вывод инструмента. Инструмент `write` (новый файл) показывает
содержимое целиком. `edit` требует точный `oldText`: не нашёл — правка не применится, «мимо» агент не перепишет.

**2) Дифф через git — эталон.** Не выходя из pi:

- `!git status` — что изменено/добавлено/удалено (вывод уйдёт модели).
- `!!git diff` — полный дифф, модели не отправляется (не расходует токены).
- `!!git diff --stat` — только файлы и число строк. `!!git diff -- src/foo.ts` — по одному файлу.
- `!!git diff --staged` — что уже в индексе.

**3) Ревью в Zed.** Git panel (`Ctrl+Shift+G`) — список изменённых файлов, выбор файла открывает дифф;
gutter — цветные метки изменённых строк; `editor: toggle git blame` — кто и когда менял строку.

**4) Accept/Reject средствами git.**

- Принять по кускам: `git add -p` (интерактивно, **в терминале**, не через `!`).
- Откатить файл: `git restore <file>` (или `git checkout -- <file>`).
- Спрятать всё: `git stash`. Закоммитить: `git add` + `git commit`.

Перед коммитом — `git status`, коммить явными путями (см. раздел 16.3). Для ревью staged-изменений:
сначала `git add -p`, потом `/review`.

| Cursor | pi / Zed |
|---|---|
| Inline before/after | дифф в транскрипте pi, `Ctrl+O` |
| Accept / Reject | `git add -p` / `git restore <file>` |
| Панель изменённых файлов | git panel Zed (`Ctrl+Shift+G`) / `git status` |
| «Кто менял строку» | gutter + `editor: toggle git blame` |
| Стадия + коммит | `git add -p` → `git commit` |

### 10.4 LSP: `.zed/settings.json` (настроено в этом проекте)

Zed сам определяет и скачивает language servers; проектный конфиг нужен, чтобы **зафиксировать** серверы,
включить inlay hints и выровнять форматирование (файл в корне, заготовка — `templates/zed-lsp/`).

```jsonc
// .zed/settings.json
{
  "format_on_save": "on",
  "languages": {
    "TypeScript": { "language_servers": ["vtsls", "..."], "tab_size": 2 },
    "JavaScript": { "language_servers": ["vtsls", "..."], "tab_size": 2 }

```

- **`vtsls`** — дефолтный TS/JS-сервер Zed (скачивается сам, без npm); `"..."` оставляет остальные дефолты,
  `"!name"` — исключает. Per-server настройки — под top-level `"lsp": { "<server>": {...} }`.
- **Inlay hints** выключены по умолчанию — включаются здесь или глобально.
- **Хоткеи LSP** уже есть из `base_keymap: VSCode`: `F12` определение, `Shift+F12` ссылки, `F2` rename,
  `Ctrl+.` code actions.

  `basedpyright`+`ruff`, нужен python-рантайм/uv; Rust: `rust-analyzer`, нужен rustup; SQL: только
  `sql-formatter` — **LSP для SQL не существует**, семантика — через Postgres MCP, раздел 13.3).
- **Не всё работает на проектном уровне** (theme/vim_mode/base_keymap — только global).

### 10.5 Сессии vs вкладки: новый чат и новая вкладка

В pi **вкладок нет** — есть **сессии**. Два действия:

| Хочу | Как | Где настройка |
|---|---|---|
| Новый чат в текущей вкладке (новая сессия) | `/new` или **`F2`** | `~/.pi/agent/keybindings.json`: `"app.session.new": ["f2", "alt+n"]` |
| Новый чат в новой вкладке (параллельный) | **`Ctrl+Shift+N`** | Zed: задача `pi` + `task::Spawn` |

Задача Zed (`%APPDATA%\Zed\tasks.json`, глобальная — работает во всех проектах):

```jsonc
[{ "label": "pi", "command": "pi",
   "use_new_terminal": true, "allow_concurrent_runs": true, "reveal": "always" }]
```

Биндинг (`%APPDATA%\Zed\keymap.json`) — перекрывает дефолтный `ctrl-shift-n` (New Window/Open Recent):

```jsonc
{ "context": "Workspace",

```

- `task::Spawn` работает и когда фокус в терминале; `command` резолвится в `pi.cmd` (проверено `where pi`);

- Встроенные вкладки терминала Zed: `ctrl-n` (в фокусе терминала) или `ctrl-shift-`` — новый терминал;

# Часть IV. Продвинутый уровень (неделя 2+)

## 11. Оркестрация: от одного агента к команде

В pi **нет встроенных субагентов** как в Cursor — из коробки оркестрация собирается из примитивов, плюс
официальный пример-расширение `subagent` (установлено) и проектное `delegate`. Правило выбора:
**начни с наименее мощного механизма, которого достаточно.**

### 11.1 Что когда использовать

| Нужно | Примитив | Где |
|---|---|---|
| Постоянные инструкции для папки | `AGENTS.md` | корень проекта / `~/.pi/agent/` |
| Переиспользуемый промпт из `/` | Prompt template | `.pi/prompts/*.md` |
| Инструкции + файлы под тип задачи | Skill | `.pi/skills/*/SKILL.md` |
| Маршрутизация запросов между моделями | Virtual model | extension `registerVirtualModel` |
| Исполняемый инструмент/команда/событие | Extension | `.pi/extensions/*.ts` |
| Изолированные субагенты (как в Cursor) | Extension `subagent` (офиц. пример) | `~/.pi/agent/extensions/subagent/` |
| Параллельные tool-вызовы + фильтрация вывода | codemode | встроенный (`+codemode`) |
| Внешние инструменты (GitHub, БД, docs) | MCP server | `mcp.json` |
| Дистрибутив набора ресурсов | Pi package | `pi install` |

### 11.2 Пять уровней

- **Уровень 0 — один агент + распределение моделей по уровням.** Один «мозг», адаптивная стоимость: виртуальная модель
  `deepseek/auto` сама выбирает `flash`/`pro`. Выгода: кэш-локальность, без ручного переключения.
- **Уровень 1 — специалисты на запрос.** Skills и шаблоны (`/plan`, `/review`, `/ship`, `code-review`)
  дают экспертизу только когда нужно — без постоянной платы за контекст.
- **Уровень 2 — изолированные субагенты.** Инструмент `subagent` (отдельный процесс pi; режимы
  single/parallel/chain) и проектное `delegate` (вложенный DeepSeek-вызов). Оба изолируют контекст:
  параллельная независимая работа (research/review/plan) не загрязняет главный контекст.
- **Уровень 3 — исполняемые агенты.** Extension-инструменты могут вызывать другие инструменты
  (`ctx.executeTool`) и делать вложенные LLM-вызовы (`ctx.modelRegistry.streamSimple`). Это и есть
  «агент как код».
- **Уровень 4 — процессная оркестрация.** Несколько `pi --print`/`--mode json`/RPC/SDK-процессов
  параллельно — пайплайны, CI, многомодульная разработка.

### 11.3 Роутер `deepseek/auto`

Пользователь выбирает одну модель `deepseek/auto`, а роутер решает физическую модель на каждый запрос
(`low` → flash, `high`/`max` → v4-pro). Три правила, на которых всё держится:

1. **Липкая маршрутизация (sticky routing).** Продолжения и повторы (retry) остаются на той же модели — иначе каждый tool-шаг = промах кэша.
   Кэш-локальность важнее «оптимального» выбора на каждом шаге.
2. **Изоляция контекста через делегирование.** Независимая работа — в субагенте с собственным промптом,
   результат возвращается одной строкой. Экономия = главный контекст не раздувается.
3. **Состояние через дерево сессии.** Роутер хранит фазу в `state` (следует за веткой, переживает
   компакцию); расширения хранят данные в `details` tool-результатов или `appendEntry`.

Использование: `/model deepseek/auto`, эскалация — `/thinking` (или `Shift+Tab`). Код — раздел 12.6.

### 11.4 Субагенты

**`subagent`** (официальный пример-расширение, установлен): модель сама вызывает его из обычного промпта:

- `Use scout to find all authentication code` — один агент;
- `Run 2 scouts in parallel: one for models, one for providers` — параллельно;
- `Use a chain: scout finds X, then planner suggests Y` — цепочка (`{previous}` передаёт вывод предыдущего шага).

Режимы: single `{agent, task}`, parallel `{tasks: [...]}` (**макс. 8 задач, 4 одновременно**),
chain `{chain: [...]}`. Каждый субагент = **отдельный процесс pi с изолированным контекстом**; в выводе —
turns/токены/кэш/`$cost`/model по каждому агенту. `Ctrl+C` убивает дочерние процессы.

Агент = markdown-файл с YAML-шапкой (пользовательские — `~/.pi/agent/agents/*.md`, проектные —
`.pi/agents/*.md`, включаются через `agentScope: "project" | "both"`):

```markdown
---
name: reviewer
description: Code review specialist
tools: read, grep, find, ls, bash
model: deepseek/deepseek-v4-pro
---
Системный промпт агента...
```

Поля: `name`, `description`, `tools`, `model` (формат `provider/id`; нет — наследует модель/thinking
родительской сессии). Агенты перечитываются при каждом вызове — правки без рестарта. Установка и
адаптация под DeepSeek — раздел 16.2. Workflow-пресеты: `/implement` (scout→planner→worker),
`/scout-and-plan`, `/implement-and-review` (промпт-шаблоны `~/.pi/agent/prompts/*.md`).

**`delegate`** (проектное расширение): то же самое, но одним вложенным вызовом DeepSeek внутри процесса
pi — быстрее и дешевле, чем отдельный процесс. Код — раздел 12.7.

### 11.5 Принципы

- **События вместо поллинга.** `pi.on(...)` (agent/tool/session/message события) для реакций и гейтов.
- **Параллельность через codemode / процессы.** Независимые чтения и greps — в `Promise.allSettled`;
  независимые задачи — в параллельные `pi --print`.
- **Экспертная эскалация.** Классификаторы (`models.classify`) могут выбирать модель по сложности задачи
  без ручного вмешательства (пример — `jev-router.ts` в `examples/extensions/`).

## 12. Свои расширения: API и эталонный код

Расширение — TypeScript-модуль с default-фабрикой `(pi: ExtensionAPI) => void`. Pi использует `jiti`,
компиляция не нужна. Файлы: `~/.pi/agent/extensions/` (глобально) или `.pi/extensions/` (проект).

### 12.1 ExtensionAPI — главные методы

| Метод | Назначение |
|---|---|
| `pi.registerTool(tool)` | LLM-вызываемый инструмент (`defineTool`) |
| `pi.registerCommand(name, {description, handler})` | `/команда` |
| `pi.registerShortcut(key, {handler})` / `pi.registerFlag(...)` | шорткаты / CLI-флаги |
| `pi.registerProvider(...)` / `pi.registerMcpServer(...)` | свой провайдер / MCP-сервер |
| `pi.registerVirtualModel({...})` | виртуальная модель-роутер |
| `pi.on(event, handler)` | подписка на события |
| `pi.sendMessage(...)` / `pi.sendUserMessage(...)` | сообщения агенту из кода |
| `pi.appendEntry(customType, data)` | долговечное состояние вне контекста |
| `pi.getActiveTools()` / `pi.setActiveTools([...])` | управление активными инструментами |
| `pi.getSettings()` / `pi.getCommands()` | настройки / команды |
| `pi.exec(cmd, args)` | shell из расширения |
| `pi.setModel(...)` / `pi.setThinkingLevel(...)` | смена модели/мышления |

### 12.2 События (выборочно)

`project_trust`, `session_start/_end/_shutdown/_tree`, `session_before_compact/_fork/_switch`,
`agent_start/_end/_before_settle/_settled`, `turn_start/_end`, `message_start/_update/_end`,
`tool_call` (можно блокировать/мутировать), `tool_result` (можно редактировать),
`tool_execution_start/_update/_end`, `context` / `context_with_system` (трансформация контекста),
`before_provider_request/_headers`, `after_provider_response`, `provider_stream_event`,
`model_select`, `thinking_level_select`, `user_bash`, `input`.

Паттерн permission-gate (подтверждать опасные вызовы) — через `tool_call` + `pi.getAllTools()` annotations
(`readOnlyHint` / `destructiveHint` / `idempotentHint` / `openWorldHint`).

### 12.3 Контексты и ModelRegistry

- **ExtensionContext** (события): `ui`, `mode`, `cwd`, `sessionManager`, `modelRegistry`, `model`,
  `scopedModels`, `thinkingLevel`, `isIdle()`, `isProjectTrusted()`, `signal`, `abort()`,
  `getContextUsage()`, `compact()`, `getSystemPrompt()`.
- **ExtensionToolContext** (execute инструмента) = + `tools` + `executeTool(name, args, opts)` (вложенные
  tool-вызовы, не попадают в транскрипт, учитываются в `nestedCalls`).
- **ExtensionCommandContext** (команды) = + `waitForIdle()`, `newSession()`, `fork()`, `navigateTree()`,
  `switchSession()`, `reload()`, `getSystemPromptOptions()`.

```ts
ctx.modelRegistry.find(provider, id)                       // модель по id
ctx.modelRegistry.findOfType("classifier", p, id)          // классификатор
ctx.modelRegistry.complete(model, context, options?)       // Promise<AssistantMessage>
ctx.modelRegistry.streamSimple(model, context, options?)   // AssistantMessageEventStream (+ .result())
ctx.modelRegistry.classify(model, {state, questions})      // классификация
ctx.modelRegistry.generateImages(model, {input})           // генерация изображений
ctx.modelRegistry.registerVirtualModel(def)                // регистрация роутера
```

`Context` = `{ systemPrompt?, messages: Message[], tools? }`; `Message` имеет `role` и `timestamp`.

### 12.4 Виртуальная модель: поля `route(request, ctx)`

| Поле `request` | Значение |
|---|---|
| `model`, `thinkingLevel` | выбранная виртуальная модель и уровень |
| `reason` | `user` / `continuation` / `retry` / `direct` |
| `previous` | физическая модель+уровень последнего успешного ответа |
| `failed` | для `retry`: физическая модель+уровень+message упавшего запроса |
| `state` | состояние роутера на ветке (JSON, переживает компакцию) |
| `messages` | конверсация запроса |
| `signal` | abort-сигнал |

Возврат: `{ model, thinkingLevel, state? }`. Нельзя роутить на другую виртуальную модель.

### 12.5 Codemode (JS-скрипты)

Включение: `"defaultTools": ["+codemode"]`. Модель пишет JS, который вызывает инструменты и не-LLM модели;
в контекст попадает только вывод скрипта. Глобальные: `tools.<name>(args)` (parallel-safe), `text()`,
`image()`, `console.log()`, `return`, `exit()`, `store(key,value)`/`load(key)`, `ALL_TOOLS`,
`searchTools(query)`, `describeTool(name)`, `describeNamespace(name)`, `models.*`.

```js
// @options: {"max_output_tokens": 2000, "timeout_ms": 60000}
const [a, b, c] = await Promise.allSettled([
  tools.grep({ pattern: "TODO" }),
  tools.find({ pattern: "**/*.spec.ts" }),
  tools.read({ path: "src/main.ts", offset: 1, limit: 200 }),
]);
return [a, b, c].map(r => r.status === "fulfilled" ? r.value : "ERR");
```

`bash` в скриптах возвращает `{ output, truncated, full_output_path?, exit_code, wall_time_seconds }`.
Лимиты: 256MB памяти, `max_output_tokens` 10000 по умолчанию, нет Node/сети/таймеров.

### 12.6 Эталонный код 1: роутер (`.pi/extensions/deepseek-router.ts`)

```ts
import type { ExtensionAPI, ExtensionContext, ModelRoute, ModelRouteRequest } from "@earendil-works/pi-coding-agent";

const PROVIDER = "deepseek";
const FLASH = "deepseek-flash";
const PRO = "deepseek-v4-pro";

function routeTo(request: ModelRouteRequest, ctx: ExtensionContext, id: string, level: string): ModelRoute {
  const model = ctx.modelRegistry.find(PROVIDER, id);
  if (!model) throw new Error(`Model ${PROVIDER}/${id} is not in the catalog`);
  return { model, thinkingLevel: level };
}

export default function (pi: ExtensionAPI) {
  pi.registerVirtualModel({
    provider: PROVIDER,
    id: "auto",
    name: "Auto (flash ↔ pro)",
    thinkingLevels: ["low", "high", "max"],
    contextWindow: 1_000_000,
    maxTokens: 384_000,
    route(request, ctx) {
      // Продолжения/повторы (retry) остаются на предыдущей модели, чтобы кэш не сбрасывался.
      if (request.reason !== "user") {
        const sticky = request.failed ?? request.previous;
        if (sticky) return { model: sticky.model, thinkingLevel: sticky.thinkingLevel ?? "low" };
      }
      // Эскалация только по явному high/max.
      if (request.thinkingLevel === "high" || request.thinkingLevel === "max") {
        return routeTo(request, ctx, PRO, request.thinkingLevel);
      }
      return routeTo(request, ctx, FLASH, "low");
    },
  });
}
```

### 12.7 Эталонный код 2: delegate (`.pi/extensions/delegate.ts`)

```ts
import { Type, type TextContent } from "@earendil-works/pi-ai";
import { defineTool, type ExtensionAPI } from "@earendil-works/pi-coding-agent";

const delegateTool = defineTool({
  name: "delegate",
  label: "Delegate",
  description:
    "Run an isolated DeepSeek sub-agent with its own system prompt and a focused task. " +
    "Use for independent work (planning, reviewing, researching) without polluting the main context.",
  parameters: Type.Object({
    role: Type.String({ description: "System prompt / persona for the sub-agent." }),
    task: Type.String({ description: "The focused task or question." }),
    model: Type.Optional(Type.String({ description: "deepseek-flash (default) or deepseek-v4-pro." })),
  }),

  async execute(_toolCallId, params, signal, _onUpdate, ctx) {
    const modelId = params.model === "deepseek-v4-pro" ? "deepseek-v4-pro" : "deepseek-flash";
    const model = ctx.modelRegistry.find("deepseek", modelId);
    if (!model) {
      return { content: [{ type: "text", text: `delegate: model deepseek/${modelId} is not available` }],
               details: { error: "model-not-found", modelId }, isError: true };
    }
    const reasoning = modelId === "deepseek-v4-pro" ? "high" : "low";
    try {
      const stream = ctx.modelRegistry.streamSimple(
        model,
        { systemPrompt: params.role,
          messages: [{ role: "user", content: params.task, timestamp: Date.now() }] },
        { reasoning, maxTokens: 8_000, signal },
      );
      const message = await stream.result();
      const text = message.content
        .filter((block): block is TextContent => block.type === "text")
        .map((block) => block.text).join("\n").trim();
      if (message.stopReason === "error" || message.errorMessage) {
        return { content: [{ type: "text", text: `delegate error: ${message.errorMessage ?? "unknown"}` }],
                 details: { error: message.errorMessage, modelId }, isError: true, usage: message.usage };
      }
      return { content: [{ type: "text", text: text || "(empty response)" }],
               details: { modelId, stopReason: message.stopReason }, usage: message.usage };
    } catch (error) {
      return { content: [{ type: "text", text: `delegate failed: ${String(error)}` }],
               details: { error: String(error), modelId }, isError: true };
    }
  },
});

export default function (pi: ExtensionAPI) { pi.registerTool(delegateTool); }
```

Ключевые идеи: `ctx.modelRegistry.find` → модель; `streamSimple` + `await stream.result()` → финальный
`AssistantMessage`; `usage` пробрасывается в результат, чтобы сессия корректно считала стоимость субагента;
валидация на границе и явная ошибка при обрыве/аборте вместо тихого «(empty response)».

## 13. MCP-серверы: внешние инструменты

MCP подключает внешние инструменты (GitHub, БД, документация, filesystem):

```bash
pi mcp add filesystem -- npx -y @modelcontextprotocol/server-filesystem .
pi mcp add docs --url https://example.com/mcp --bearer-token-env-var DOCS_TOKEN
pi mcp list          # проверка
```

Конфиг: `~/.pi/agent/mcp.json` (глобально) или `.pi/mcp.json` (проект). Формат — стандартный `mcpServers`:

```jsonc
{ "mcpServers": {
    "filesystem": { "command": "npx", "args": ["-y", "@modelcontextprotocol/server-filesystem", "."] },
    "github":     { "url": "https://api.githubcopilot.com/mcp/", "exposure": "deferred" }
} }
```

**Exposure** (как модель достигает инструментов сервера):

| Режим | Поведение | Когда |
|---|---|---|
| `codemode` (default) | вызывается из codemode-скриптов, модели не декларируется | общие серверы, объединять/фильтровать вызовы |
| `deferred` | не декларируется, пока `tool_search` не найдёт совпадение | большие серверы |
| `direct` | декларируется модели как обычный инструмент | маленькие частые наборы |
| `hidden` | зарегистрирован, но недоступен | выключить/секретные |

`toolExposure` переопределяет exposure для отдельных инструментов (ключи = имена, `*` — wildcard).
Инструменты именуются `mcp__<server>__<tool>`. Внутри сессии — `/mcp` (статус, sign-in, exposure).

### 13.1 Serena — семантические инструменты кода (MCP + LSP)

Serena даёт агенту **семантические** инструменты кода (символы, ссылки, определения, поиск, безопасный
rename) через language servers (LSP). Живая копия — `.pi/mcp.json` + `.serena/project.yml`, заготовка —
`templates/mcp/`.

```jsonc
// .pi/mcp.json
{ "mcpServers": { "serena": {
    "command": "uvx",
    "args": ["--from", "serena-agent", "serena", "start-mcp-server", "--context", "ide", "--project-from-cwd"],
    "description": "LSP-based semantic code tools: symbols, references, definitions, and code search (Serena).",
    "exposure": "deferred",
    "env": { "PYTHONUTF8": "1" }   // cp1251-Windows: форсируем UTF-8 в stdio
} } }
```

- PyPI-пакет `serena-agent`, entrypoint — `serena`; без `--from` uvx не найдёт бинарь.
- **`--context ide`** — pi уже имеет read/edit/grep/find, поэтому Serena режется до 22 семантических +
  memory-инструментов (без дублей). Для голого клиента — `claude-code`/`agent`.
- **`--project-from-cwd`** — pi запускает stdio-сервер из корня проекта, Serena сама находит ближайший
  `.serena/project.yml` (без хардкода путей).
- **`.serena/project.yml`** — список `language_servers` (typescript/markdown/yaml/json для этого репо;
  полный список языков — в docs Serena). `project.local.yml` и `logs/`/`memories/` — машинно-локальные, не коммитятся.
- **Проверка:** `pi mcp list` (→ `serena: connected, 22 tools`) и
  `uvx --from serena-agent serena project health-check .` (действительно запускает LS и вызывает symbol-инструменты).

### 13.2 Playwright MCP — реальный браузер

`@playwright/mcp` даёт агенту настоящий браузер (navigate/click/fill/snapshot/screenshot) вместо
«представь, что страница выглядит так» — фактические DOM-снапшоты и скриншоты.

```jsonc
{ "mcpServers": { "playwright": {
    "command": "npx",
    "args": ["-y", "@playwright/mcp@latest", "--headless", "--caps", "vision",
             "--file-paths", "relative", "--output-dir", ".playwright-mcp"],
    "exposure": "deferred"
} } }
```

- **`--headless` обязателен** — у сервера дефолт headed (окно на каждый запуск). `--caps vision` — модель
  получает скриншоты. Профиль персистентный (логины переживают сессии); `--isolated` — для одноразовых.
- Браузеры: `npx playwright install chromium`. Скриншоты пишутся в `.playwright-mcp/`.
- **LSP не нужен:** тесты — обычный TypeScript, покрывается `vtsls` (Zed) / `typescript` (Serena).

### 13.3 PostgreSQL MCP — схема и запросы

`@henkey/postgres-mcp-server`: исследование схемы, параметризованные запросы, миграции. Подключён с
`"enabled": false` — локально нет ни psql, ни docker, ни `DATABASE_URL` (сервер, падающий при каждом
старте, — шум, а не безопасность).

```jsonc
{ "mcpServers": { "postgres": {
    "command": "npx",
    "args": ["-y", "@henkey/postgres-mcp-server@latest"],
    "env": { "POSTGRES_CONNECTION_STRING": "${DATABASE_URL}" },   // pi раскрывает ${VAR} в env
    "exposure": "deferred",
    "enabled": false      // включить: export DATABASE_URL=... → /mcp → Enable
} } }
```

- **Секреты не коммитятся:** строка подключения живёт в `DATABASE_URL` (shell profile), в репо — только `${DATABASE_URL}`.
- **LSP для SQL не существует** (ни в Zed, ни в Serena) — семантика через Postgres MCP, форматирование —
  внешний `sql-formatter` (dialect `postgresql`) в Zed.

### 16.3 Типичные ошибки (каждая — из реального опыта)

- **`pi --print` наследует env родителя:** запущенный из сессии pi, он получит `PI_MODEL` / `PI_PROVIDER`
  / `PI_REASONING_LEVEL` и проигнорирует `defaultModel` из settings.json. Для проверок задавай модель
  явно: `--model deepseek/deepseek-flash --thinking low`. `--model` принимает `provider/id` и суффикс
  `:<thinking>`.
- **cp1251-Windows и эмодзи.** Python на русской локали пишет в консоль в cp1251; `serena project
  health-check` печатал «✅ Health check passed» и падал `UnicodeEncodeError` — **exit 1 при реальном
  успехе**. Вывод: не верить коду возврата слепо, читать текст. Лечится `env: { "PYTHONUTF8": "1" }`
  для MCP-сервера.
- **Playwright MCP по умолчанию headed** — на каждый запуск открылось бы окно браузера. Нужен явный
  `--headless` (+ `--caps vision`, `--output-dir .playwright-mcp`, `--file-paths relative`).
- **SQL-LSP не существует** — ни в Zed (только грамматика), ни в Serena (нет SQL backend).
  «LSP для PostgreSQL» — это честно не LSP, а семантический слой Postgres MCP + `sql-formatter`.
- **Не подключай сервер, который заведомо не подключится.** Без psql/docker/`DATABASE_URL` Postgres MCP
  стоит с `"enabled": false`. Включается одной командой в `/mcp`, когда база появится.
- **Секреты — только через env.** `${DATABASE_URL}` в `env` раскрывается pi; в репозитории — только имя
  переменной.
- **Zed project settings — не всё проектно.** `.zed/settings.json` перекрывает global, но `theme`,
  `vim_mode`, `base_keymap` работают только в user settings; `keymap.json` — вообще только global.
- **Git: `git mv` + `git commit` без путей коммитит весь индекс.** Staged-rename попал в «чужой» коммит.
  Лечится `git reset --soft <base>` + путь-скоупные коммиты (безопасно, пока не запушено). Перед коммитом —
  `git status`, коммить явными путями.
- **Не плоди md-файлы, рассинхроненные с кодом.** Код — источник истины; устаревшие md заставляют агента
  вести себя непредсказуемо и расходовать токены впустую.

### 16.4 Методология настройки (что сработало)

1. **Разведай** текущее состояние (`ls ~/.pi/agent`, `.pi/mcp.json`, Zed settings).
2. **Не изобретай ключи.** Схему — из первоисточника: pi MCP → `docs/mcp.md` в установке; Zed →
   `assets/settings/default.json` в репо `zed-industries/zed`; Serena → `serena <cmd> --help` и её docs.
3. **Сконфигурируй → проверь реальным подключением** (`pi mcp list` показывает tool count и ошибки), а не
   парсингом JSON.
4. **Оформи шаблон** в `templates/`, обнови этот документ, закоммить.

Правило: «ключ, которого я не видел в схеме/help — не пишу». Это дешевле, чем отладка сломанной конфигурации.

## 17. Перенос опыта в другие проекты

Опыт переносится в новые проекты `~/Work` — но **не копированием папки целиком**: у pi есть глобальный
(user) и проектный уровни ресурсов, раскладывай их по двум критериям — цена контекста и дрейф копий.

### 17.1 Инвентарь: что куда

| Ресурс | Куда оптимально | Почему |
|---|---|---|
| Общие правила: token-economy, Гамильтон/Акин, DeepSeek | **global**: `~/.pi/agent/AGENTS.md` | всегда в контексте → одна копия вместо N, контекст короче |
| Специфика репо: структура, команды, пути | **проект** (короткий шаблон) | уникально для каждого репозитория |
| `deepseek-router.ts`, `delegate.ts`, `deepseek-balance.ts` | **global**: `~/.pi/agent/extensions/` | чистые инструменты, не зависят от проекта |
| `/plan`, `/review`, `/ship` | **global**: `~/.pi/agent/prompts/` | workflow один на все проекты |
| `code-review`, `engineering-principles` | **global**: `~/.pi/agent/skills/` | типовая экспертиза; reference-пути относительны skill-директории |
| `defaultTools`, `hideThinkingBlock`, `showCacheMissNotices` | **global**: `~/.pi/agent/settings.json` | тогда новый проект = ноль конфига |
| `tools/pi-cost/` | проект: **junction** на канон | один файл-источник, без копий |
| MCP+LSP: `templates/mcp/` | **шаблон**: копировать в каждый проект | `language_servers`/`project_name` уникальны для репо; `--project-from-cwd` и `${DATABASE_URL}` делают записи переносимыми без секретов |
| Zed LSP: `templates/zed-lsp/` | **шаблон**: копировать `.zed/settings.json` | `languages`/`tab_size` уникальны для репо; keymap.json — только global |
| `PI_ZED_DEEPSEEK_MASTERY.md` | **остаётся здесь** | знание-база; в новые проекты не копируется |

Почему так: (1) **токены** — AGENTS.md и описания инструментов грузятся в каждый сеанс, дублировать их
по проектам = платить за тот же текст N раз; (2) **дрейф копий** — расходящиеся копии (мы сами допустили:
29- и 45-законные версии Акина); (3) **trust** — проектные ресурсы требуют подтверждения в каждом новом
проекте, глобальные доверены один раз.

### 17.3 Вариант B — канон без дрейфа: pi-пакет

`pi install` ставит пакет с extensions+skills+prompts одним юнитом (npm/git/local path; см.
`docs/packages.md`). Структура пакета-канона:

```text
pi-harness/
├── package.json      # {"name":"zed-pi-harness","keywords":["pi-package"]}
├── extensions/       # deepseek-router.ts, delegate.ts
├── skills/           # code-review/, engineering-principles/
└── prompts/          # plan.md, review.md, ship.md
```

```bash

pi install -l ./pi-harness     # только в текущий проект (.pi/settings.json)
pi install git:github.com/<you>/zed-pi-harness@v1   # версионированно, обновление: pi update --extensions
```

- **Local path грузится из пути без копирования** → правишь канон в одном месте, все проекты видят
  изменения сразу. Ноль дрейфа.
- Хост-пакеты (`@earendil-works/pi-ai`, `pi-coding-agent`) — в `peerDependencies: {"*"}`, не в
  `dependencies` (иначе дубликат классов и warning).
- Проектные пакеты грузятся только после подтверждения trust.
- Если пойдёшь по B — Zed_and_Pi.dev тоже переведи на пакет (иначе здесь останется старая копия).

потребители; global-уровень ничего не блокирует).
