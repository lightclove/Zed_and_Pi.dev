# Zed_and_Pi.dev — харнесс и заготовки для pi.dev + DeepSeek

**pi** — ИИ-агент, который работает в терминале: читает файлы, выполняет команды и сам правит код
по вашим указаниям. **DeepSeek** — семейство моделей, на которых он работает.
**Харнесс** (англ. _harness_, «оснастка») — набор конфигурации, который настраивает агента под рабочий процесс:
расширения, скиллы, промпты и настройки; в этом репозитории он живёт в `.pi/`.

**Три вещи в одном репозитории:**

1. **Краткое руководство** — `PI_ZED_DEEPSEEK_MASTERY.md`: от первого запуска до собственных
   расширений и субагентов (агентов-помощников).
2. **Рабочий харнесс** — `.pi/`: расширения (код на TypeScript, добавляющий агенту новые
   возможности), скиллы (инструкции, которые агент читает по требованию) и промпты (шаблоны
   команд `/plan`, `/review`, `/ship`).
3. **Переносимые заготовки** — `templates/` и `tools/pi-cost/`: то, что копируется в любой новый
   проект под `~/Work`.

## Детальное описание файлов

### Корень

#### `PI_ZED_DEEPSEEK_MASTERY.md`

Главный документ репозитория — краткое руководство по работе с pi.dev + DeepSeek, включая справочник
клавиш терминала и редактора промпта (навигация, удаление по словам, очистка ввода).

| Часть                   | Разделы | Что внутри                                                                                                                                       |
| ----------------------- | ------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| I. Первый запуск        | 1–3     | Установка и проверка (Git Bash, ключ), экран, стоп, навигация, сессии, справочник команд/хоткеев/CLI/env                                         |
| II. Как устроено        | 4–7     | Ментальная модель pi, настройки `settings.json`, цены и кэш DeepSeek, десять правил экономии токенов + измерение денег (включая баланс в футере) |
| III. Ежедневная работа  | 8–10    | Рабочий цикл `/plan → код → /review → /ship`, чтение диффов (pi/git/Zed), Zed рядом (LSP, проброс клавиш, вкладки)                               |
| IV. Продвинутый уровень | 11–14   | Оркестрация (5 уровней, роутер, субагенты), API расширений + эталонный код, MCP-серверы, дорожная карта                                          |
| Приложения              | 15–17   | Инвентарь проекта, журнал чисел и типичных ошибок, перенос опыта в другие проекты                                                                |

Особенности: задания «сделай сам» в конце каждой части.

#### `AGENTS.md`

Инструкции, которые pi читает в каждой сессии этого проекта:

- **Workflow** — исследовать до правки (`find`/`grep`/`ls` → точечные `read`/`edit`), одна
  логическая правка за ход, коммитить рабочие состояния.
- **Инженерные принципы** — свод правил из двух первоисточников.
- Маргарет Гамильтон (H1–H5) —
  руководитель разработки бортового ПО лунной программы Apollo, автор термина «Software
  Engineering»;
  Её принцип: ловить ошибки как можно раньше, а не после.
  «Законы Акина» (A1–A26) —
  сборник инженерных правил Дэвида Акина, профессора Мэрилендского университета; например,
  «решения принимаются числами, а не мнениями» и «не строй больше, чем требует задача».
  Полные списки и ссылки на источники — в скилле `engineering-principles`
  (файлы `references/hamilton.md` и `references/akin-laws.md`).
- **Fact-check gate** — каждое утверждение в ответе агента классифицируется как proven
  (подтверждено проверкой) / unverified (не проверено), с обязательной строкой в конце ответа
  `Fact-check: <n> proven / <m> unverified / <k> checks`.
- **Модели** — `deepseek-flash` по умолчанию, эскалация на `deepseek-v4-pro` для сложных задач,
  стабильный промпт и инструменты для сохранения кэша провайдера.
- **Гигиена** — не коммитить в git секреты (ключи API, пароли) и файл `auth.json`, в котором pi
  хранит учётные данные провайдеров моделей.

### `.pi/` — проектный харнесс

Файлы этого каталога pi загружает только после подтверждения trust — доверия к проекту, которое
pi запрашивает при первом запуске в папке.

#### `.pi/settings.json`

```jsonc
{
  "defaultTools": ["+grep", "+find", "+ls", "+codemode", "+tool_search"],
  "hideThinkingBlock": true,
  "showCacheMissNotices": true,
}
```

Проектный уровень поверх глобального `~/.pi/agent/settings.json`:
добавляет инструменты для дешёвого исследования (`+` = добавить к набору по умолчанию, а не заменить его),
прячет thinking-блоки (рассуждения модели) и включает уведомления о промахах кэша.

#### `.pi/mcp.json`

Три MCP-сервера (MCP, Model Context Protocol, — стандарт подключения внешних инструментов к
агенту), все с `exposure: deferred` (инструменты не раздувают базовый промпт, а подгружаются по
запросу через `tool_search`):

- **serena** — семантические инструменты кода через LSP (`uvx --from serena-agent … --context ide
  --project-from-cwd`, `env.PYTHONUTF8=1` для Windows cp1251); у неё есть свой веб-дашборд —
  `http://127.0.0.1:24282/dashboard/` (раздел 13.5 руководства);
- **playwright** — реальный браузер (`--headless --caps vision`, скриншоты в `.playwright-mcp/`);
- **postgres** — схема и запросы (`enabled: false`, строка подключения из `${DATABASE_URL}`, в репо
  секретов нет).

#### `.pi/extensions/deepseek-router.ts`

Виртуальная модель **`deepseek/auto`** — маршрутизатор, который сам выбирает физическую модель
(`deepseek-flash` или `deepseek-v4-pro`) на каждый запрос:

- `low` → flash, `high`/`max` → v4-pro;
- **липкая маршрутизация (sticky routing)**: продолжения и повторы (retry) остаются на предыдущей
  модели, чтобы не сбрасывать префикс-кэш (кеш на стороне DeepSeek, который делает повторный ввод
  в десятки раз дешевле);
- валидация на границе: модель не в каталоге → явная ошибка, а не неявное переключение на первую
  попавшуюся (H1/H3).

Использование: `/model deepseek/auto`, эскалация — `/thinking` или `Shift+Tab`.
Разбор кода — раздел 12.6 руководства.

#### `.pi/extensions/delegate.ts`

Инструмент **`delegate`** — изолированный субагент (отдельный запрос к модели со своим промптом,
результат которого не засоряет основной разговор) одним вложенным вызовом DeepSeek:

- параметры `role` / `task` / `model` валидируются на границе;
- `ctx.modelRegistry.streamSimple` → финальный `AssistantMessage`;
- `usage` пробрасывается в результат — сессия корректно считает стоимость субагента;
- при сбое возвращается явная ошибка (`isError` + `details`), а не молчаливое «(empty response)» (Акин 2).

#### `.pi/extensions/deepseek-balance.ts`

Живой баланс аккаунта DeepSeek в футере TUI (строке статуса внизу экрана, цифры для примера, условные):
`deepseek $46.44 left · this session -$0.149`.

- при старте сессии один раз запрашивает реальный баланс с `https://api.deepseek.com/user/balance`
  (ключ — из провайдера pi, не зашит в код);
- между запросами вычитает траты текущей сессии из usage-записей (записей о потраченных токенах и
  деньгах);
- `/balance` — принудительная повторная синхронизация;
- ошибки показываются как есть (`HTTP 401`, `no DeepSeek API key`).

Как установить и что внутри — раздел 7.3 руководства.

#### `.pi/prompts/` — промпт-шаблоны (`/команды`)

| Файл        | Команда           | Что делает                                                                                                                                                                                                                   |
| ----------- | ----------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `plan.md`   | `/plan [goal]`    | План до кода: цель, допущения (A9), отвергнутые альтернативы (A12), пошаговый чек-лист с дешёвыми проверками (H1), риски. Код не пишет.                                                                                      |
| `review.md` | `/review [focus]` | Ревью проиндексированных (staged) изменений: ошибки ловятся рано или в рантайме (H1/H3), пути отказов (A2), проверка чужих утверждений (A16/A19). Формат: `file:line`, severity, фикс; вердикт ship / fix then ship / block. |
| `ship.md`   | `/ship [scope]`   | Прод-чеклист: **numbers gate** (контроль по числам — тесты, проверка типов, стоимость; Акин 1/H5), обновление тестов/доков, финальный sanity-проход (Акин 26), commit message. Пушить без подтверждения запрещено.           |

#### `.pi/skills/code-review/`

- `SKILL.md` — формат ревью: `[severity] file:line — проблема`, почему важно, конкретный
  фикс; severity: critical/major/minor; вердикт ship / fix then ship / block.
- `references/checklist.md` — чек-лист, который агент читает перед ревью.

#### `.pi/skills/engineering-principles/`

- `SKILL.md` — таблица правил H1–H5 (Гамильтон) и законов Акина (A1–A26) с конкретным
  поведением в этом харнессе + таблица гейтов (где какое правило срабатывает: план/код/ревью/шип).
- `references/hamilton.md` — канонический список принципов Гамильтон.
- `references/akin-laws.md` — канонический список законов Акина с маппингом на харнесс.

Скилл срабатывает при планировании архитектуры, проектировании интерфейсов и проверке изменений
перед сдачей (гейты).

### `.zed/settings.json` — LSP в Zed (project-level)

LSP (Language Server Protocol) — протокол, по которому редактор получает от языкового сервера
навигацию по коду, автодополнение и диагностику.
Zed сам скачивает языковые серверы; этот файл фиксирует выбор и включает полезное:

- `format_on_save: "on"` (форматировать при сохранении);
- TypeScript/JavaScript → `vtsls` (языковой сервер TypeScript), `tab_size: 2`;
- `inlay_hints` включены (подсказки типов прямо в коде);
- заготовка с блоками Python (`basedpyright`+`ruff`), Rust (`rust-analyzer`), SQL (`sql-formatter`)
  — в `templates/zed-lsp/`.

Глобальные предпочтения (theme, vim_mode, base_keymap) остаются в `%APPDATA%\Zed\settings.json` —
на проектном уровне они не работают.

### `.serena/` — LSP-бэкенд Serena

Serena — сервер семантического поиска по коду (символы, ссылки, определения) поверх LSP.
Её конфиг:

- `project.yml` — `project_name: "zed-and-pi-dev"` + список `language_servers`
  (typescript/markdown/yaml/json) + полный справочник языков в комментариях.

Serena сама находит этот файл из корня проекта (`--project-from-cwd`) и скачивает нужные языковые
серверы. Проверка: `uvx --from serena-agent serena project health-check .`

### `templates/` — переносимые шаблоны (заготовки конфигов)

Живая копия конфигов лежит в корне (`.pi/mcp.json`, `.zed/settings.json`, `.serena/project.yml`) и
уникальна для этого репо; `templates/` — то, что копируется в новые проекты с поправкой
`project_name` / `language_servers` / `tab_size`.

#### `templates/mcp/`

- `mcp.json` — три сервера (serena, playwright, postgres), все `deferred`, postgres `enabled: false`.
- `serena.project.yml` — заготовка с таблицей языков.
- `README.md` — полная инструкция: предпосылки (uv/uvx, Node), готовность каждого сервера
  («Ready when»), проверки (`pi mcp list`, `health-check`), типичные ошибки (headed Playwright, cp1251,
  секреты через env), таблица exposure-режимов.

#### `templates/zed-lsp/`

- `settings.json` — активный TS/JS-блок + закомментированные Python/Rust/SQL.
- `README.md` — где живут настройки (global vs project), как выбрать language server (`"..."`/`"!name"`),
  таблица языков, заметки (SQL-LSP не существует, inlay hints выключены по умолчанию, что не работает
  на проектном уровне).

### `tools/pi-cost/` — отчёт по деньгам

- `pi-cost.mjs` — агрегатор JSONL-сессий pi (JSONL — формат, где каждая строка файла — отдельная
  JSON-запись; так pi хранит историю сессий): суммирует **все** записи (включая заброшенные
  ветки — это реальный расход), считает долю попаданий в кэш `hit% = cacheRead / (input +
  cacheRead)`, reasoning-токены и стоимость. Флаги: `--today`, `--last N`, `--top N`, `--json`.
- `README.md` — семантика, ограничения (схема привязана к формату pi 1.x; при обновлении pi сверять
  с `/session`).

Запуск: `node tools/pi-cost/pi-cost.mjs --last 7 --top 5`.

## Быстрый старт

```bash
git clone https://github.com/lightclove/Zed_and_Pi.dev.git
cd Zed_and_Pi.dev
pi            # подтвердить trust → /reload
```

Дальше — открыть `PI_ZED_DEEPSEEK_MASTERY.md` и идти по частям I–IV.
Харнесс загрузится сам после trust; для переноса в свой проект — `templates/` и раздел 17 руководства.

Требования: Git, pi (v1.x), ключ DeepSeek в `DEEPSEEK_API_KEY`, Node.js (для MCP и
`pi-cost`), `uvx` (для Serena), Zed — опционально.
